# Unit 21: Full Migration to Roc 0.1.0-RC2 (Type Modules, GolemJson, and Zero-Warning Modernization)

## 1. Problem Statement & Motivation

The Roc language team has officially released **Roc 0.1.0-RC2** (`0.1.0-RC2`, commit `ee835686f9eae076bee7422c26e7cf8deb20aa0e`). This is a pivotal release milestone moving Roc toward its 1.0 release.

When compiling `roc-golem` with `0.1.0-RC2`, several breaking changes and deprecations are diagnosed:

1. **Reserved Module Name `Json.roc`**:
   - `Json` is now a reserved builtin type in the Roc language.
   - Naming a file `platform/Json.roc` causes a fatal compiler error: `This file is named Json.roc, but Json is the name of a builtin type. Module names that match builtin types are reserved for those types...`.
   - Exposing `Json` in `platform/main.roc` or importing `Json` creates duplicate definitions and reserved type name errors (`This import cannot bind Json because that name is reserved for a builtin type`).

2. **JSON Parser Signature & Type Inference**:
   - `Json.parse` in `0.1.0-RC2` returns `Try(a, [InvalidJson(Str)])` with strict tag union constraints.
   - Prior code in `platform/Json.roc` and `platform/Golem.roc` declared open tag unions (`[InvalidJson(Str), ..errs]`) or catch-all wildcard matches (`Err(_) => ...`), resulting in compiler type mismatch errors against the exact type expected by `Json.parse`.

3. **Module Header Deprecation in Favor of Type Modules**:
   - Roc 0.1 deprecates traditional `module [export1, export2]` headers:
     `The module header is deprecated. Type modules (headerless files with a top-level type matching the filename) are now the preferred way to define modules.`
   - In modern Roc, a file `Foo.roc` declares a top-level nominal type `Foo := [].{ ... }` (or with state payload), and all exposed types and values are attached as associated items within the block. Anything outside the block is private to the file.

4. **Redundant Expose Errors on Type Modules**:
   - Importing a type module automatically exposes its nominal type. Explicitly listing the module's own name in `exposing [Foo]` (e.g. `import pf.Effect exposing [Effect, map]`) is now a compiler error: `redundant expose: Redundantly exposing Effect when importing pf.Effect. The type Effect is automatically exposed when importing a type module. Remove Effect from the exposing clause.`

5. **Exhaustive Pattern Matching Warnings on Infallible Closures**:
   - Matching `Err(_)` on closures whose inferred return type contains only `Ok(...)` produces compiler warnings: `The second branch of this match can never match. Err(_) => False`.

6. **Outdated Toolchain Pins**:
   - `tooling/build.sh`, `.github/workflows/ci.yaml`, and `.github/workflows/release.yaml` are pinned to `nightly-2026-09-29-7f11a82`.

The goal of this unit is a comprehensive, clean migration to **Roc 0.1.0-RC2**, completely eliminating all errors and deprecation warnings across the platform, examples, tests, build tooling, and documentation.

## 2. Technical Design & Architecture

### 2.1 Renaming `platform/Json.roc` to `platform/GolemJson.roc`

To eliminate the reserved type name conflict with Roc's builtin `Json`, the platform's JSON utility module is renamed to `platform/GolemJson.roc`:

- Platform header in `platform/main.roc`:
  ```roc
  platform "golem"
      requires { [State : state] for agent : Golem.Agent(state) }
      exposes [
          Golem,
          Types,
          GolemJson,
          Parse,
          Effect,
      ]
      ...
  ```
- Platform entry imports:
  ```roc
  import GolemJson exposing [encode, decode, decode_or, escape]
  ```
- `platform/Golem.roc` imports:
  ```roc
  import GolemJson as PlatformJson exposing [escape]
  ```
- Downstream consumer imports:
  ```roc
  import pf.GolemJson exposing [encode, decode, decode_or, escape]
  ```
  *(Note: Builtin `Json.to_str` and `Json.parse` remain accessible globally in user code without imports).*

### 2.2 Modernizing Modules to Type Modules

All platform files (`Types.roc`, `Parse.roc`, `GolemJson.roc`, `Golem.roc`) and multi-file example modules (`canary_release/ReleaseCoordinator.roc`, `canary_release/DiagnosticsWorker.roc`, `canary_release/Types.roc`) will be modernized into headerless Type Modules.

#### A. `platform/Types.roc`
Header removed. Declares nominal type `Types := [].{ ... }` exposing:
- `Result(ok, err) : Try(ok, err)`
- `SecretHandle := [SecretHandle(U32)]`
- `wrapSecretHandle : U32 -> SecretHandle`
- `unwrapSecretHandle : SecretHandle -> U32`
- `SecretHeader`, `HttpRequest`, `AgentMode`, `HttpMount`, `MethodDeclaration`
- `ToolDefinition`, `ToolParameter`, `ToolCall`, `ToolResult`
- `PersistenceMode`, `LogLevel`, `Metadata`

#### B. `platform/GolemJson.roc`
Header removed. Declares nominal type `GolemJson := [].{ ... }` exposing:
```roc
import Types exposing [Result]

GolemJson := [].{
    encode : a -> Str where [a.Json.Encodable([])]
    encode = |val|
        Json.to_str(val)

    decode : Str -> Result(a, Str) where [a.Json.Parseable([InvalidJson(Str)])]
    decode = |json_str|
        match Json.parse(json_str) {
            Ok(val) => Ok(val)
            Err(InvalidJson(msg)) => Err("Invalid JSON: ${msg}")
        }

    decode_or : Str, a -> a where [a.Json.Parseable([InvalidJson(Str)])]
    decode_or = |json_str, default_val|
        match decode(json_str) {
            Ok(val) => val
            Err(_) => default_val
        }

    escape : Str -> Str
    escape = |input| ...
}
```

#### C. `platform/Parse.roc`
Header removed. Declares nominal type `Parse := [].{ ... }` exposing:
- `parseU64`, `parseU32`, `parseU16`, `parseU8`, `parseU64Or`, `parseU32Or`
- `parseI64`, `parseI32`, `parseI16`, `parseI8`, `parseI64Or`, `parseI32Or`
- `parseF64`, `parseF64Or`
Internal byte parsing helpers remain outside the block as private module-level functions.

#### D. `platform/Golem.roc`
Header removed. Top-level imports at top of file, followed by `Golem := [].{ ... }` enclosing:
- Type aliases: `Agent(state)`, `ErasedAgent`, `Spec(state)`, `Method(state)`, `Handler(state)`, `Tool(state)`, `StatelessTool`
- Agent constructors & builders: `agent`, `agentWith`, `simpleAgent`, `define`, `defineAgent`, `defineEphemeral`, `build`, `bundle`, `bundle2`..`bundle5`, `bundleWith`, `bundleAll`, `erase`
- Method & Tool registrars: `method`, `register`, `registerReadOnly`, `registerEphemeral`, `registerTyped`, `registerReadOnlyTyped`, `registerEphemeralTyped`, `registerEffectful`, `registerEffectfulTyped`, `withHttpMount`, `withAgentHttpMount`
- Tool helpers: `tool`, `toolJson`, `statefulTool`, `statelessTool`, `statelessToolJson`, `effectfulTool`, `effectfulToolJson`, `effectfulStatelessTool`, `effectfulStatelessToolJson`, `withTools`, `withToolHandler`, `withStatelessToolHandler`, `withEffectfulToolHandler`, `withEffectfulStatelessToolHandler`, parameter builders (`param`, `numberParam`, etc.), and tool dispatchers
- Response helpers & effect primitives: `reply`, `readOnly`, `stay`, `fail`, `replyJson`, `readOnlyJson`, `runEffect!`, and all high-level effect primitives
- Update `agentWith` / `deserializeState` where clause from `[InvalidJson(Str), ..errs]` to exact `[InvalidJson(Str)]`.

#### E. `platform/Effect.roc`
Already a Type Module `Effect(a) := [Effect({} => a)].{ ... }`. Kept intact without deprecation warnings.
