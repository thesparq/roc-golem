# Spec 18: v1.2.0 Remediation & Developer Experience Polish

## Overview

Following the release of `roc-golem` v1.2.0, a comprehensive audit identified high-priority fixes across distribution packaging integrity, version consistency, documentation precision, and runtime verification on Golem Cloud 1.6.3.

This specification details the remediation plan, implementation steps, and verification results.

---

## Identified Issues & Prioritization

### P0 (Blocker) — Platform Release URL 404 in README
- **Root Cause**: The local packaging tool `pack_platform` calculates the BLAKE3 hash of the local tarball (`7tvjAkNOXfbP1LmNSFknACmMXKul4-q3geVJkood0r8.tar.zst`). When GitHub Actions ran the release workflow, archive generation timestamps produced a different content hash (`gaeT4elx5DUSLROJgzbAXG5ewzzf71k35bQVGHmsYPQ.tar.zst`). The README referenced the local hash, causing a 404 error when developers copied the platform snippet.
- **Fix**:
  1. Update `README.md` to reference the published content-addressed archive:
     `https://github.com/thesparq/roc-golem/releases/download/v1.2.0/gaeT4elx5DUSLROJgzbAXG5ewzzf71k35bQVGHmsYPQ.tar.zst`
  2. Document the stable named platform URL alias:
     `https://github.com/thesparq/roc-golem/releases/download/v1.2.0/roc-golem-v1.2.0.tar.zst`

### P1 (High) — Version String Inconsistencies & Defaults
- **Root Cause**: Multiple build and deployment configurations contained stale default version strings from v1.1.0 and v1.0.0.
- **Fixes**:
  - `tooling/build.sh`: Bump fallback `$TAG` in `package_platform`, `package`, `release`, and `all` commands from `v1.1.0` to `v1.2.0`.
  - `golem.yaml`: Update `staticFallback` from `"v1.0.0"` to `"v1.2.0"`.
  - `.github/workflows/release.yaml`: Update manual release workflow default tag input from `"v1.1.0"` to `"v1.2.0"`.

### P1 (High) — `getOplogIndex` Wasm32 Limitation Documentation
- **Root Cause**: On Golem Cloud wasm32 guest workers, `getOplogIndex` currently returns `0` due to a WIT export gap in Golem 1.6. If a developer unknowingly passes `0` to `revertAgent`, the worker is rolled back to oplog index 0 (initial state).
- **Fix**: Update the Primitives table in `README.md` with an explicit developer warning and guidance.

### P1 (High) — Live Layer 4 Verification on Golem Cloud 1.6.3
- **Root Cause**: Need authoritative runtime proof confirming that all 4 Roc agents (`counter`, `canary_release`, `ai_tool`, `streaming_agent`) and their transitive WIT dependencies (including `wasi:clocks/types@0.3.0` via `golem:api/retry@1.5.0`) deploy, run, and pass stateful multi-turn durability tests on a clean native Golem 1.6.3 server.
- **Fix**: Execute `tooling/test_runtime.sh`, confirm all suites pass, and archive the live log in `docs/demo/v1.2.0-live-test.log`.

### P2 (Minor) — Historical Changelog & Progress Tracker Sync
- **Fixes**:
  - `CHANGELOG.md`: Correct v1.0.0 release date from `2026-10-31` to the actual git tag date `2026-11-08`.
  - `docs/progress-tracker.md`: Update stale runtime references (`v1.6 / 1.2.5` -> `Golem 1.6.3`).
